# RSS 통학 읽을거리 수집기

GitHub Actions로 RSS를 하루 한 번 수집해 `articles.json`을 갱신합니다.

## 실행 시간
- 매일 한국시간 오전 6시 (`UTC 21:00`)
- GitHub Actions의 `workflow_dispatch`로 수동 실행 가능

## 설치 방법

1. GitHub에서 새 저장소를 만듭니다.
2. 이 폴더의 파일과 디렉터리를 저장소 루트에 업로드합니다.
3. 저장소의 **Settings → Actions → General → Workflow permissions**로 이동합니다.
4. **Read and write permissions**를 선택하고 저장합니다.
5. **Actions** 탭에서 `Update RSS articles`를 선택합니다.
6. **Run workflow**를 눌러 수동 실행합니다.

저장소가 조직(Organization) 소유라면 조직 정책이 쓰기 권한을 제한할 수 있습니다.

## RSS 주소 관련 참고

사용자가 제공한 `The Economist`, `Financial Times`, `KDI` 주소는 홈페이지 주소이며 RSS 피드 주소가 아닐 수 있습니다. 이 스크립트는 입력된 주소를 그대로 확인하고, 피드 항목을 읽지 못하면 해당 소스만 오류 로그에 남긴 뒤 다음 소스로 넘어갑니다. 실제 RSS/Atom 주소를 확인한 뒤 `scripts/fetch_rss.py`의 `FEEDS`에서 교체하세요.

`전자신물`은 `전자신문`으로 표기를 바로잡았습니다.

## 데이터 정책

- `articles.json`에는 제목, URL, 출처, 카테고리, 읽기 시간, 100자 이하 요약, 발행일만 저장합니다.
- 기사 본문은 읽기 시간 계산에만 사용하고 저장하지 않습니다.
- 본문을 추출하지 못하면 RSS 요약 길이로 추정하며 `estimated: true`를 붙입니다.
- 최근 60일 이내 기사 중 최신순 최대 200개를 유지합니다.
- 같은 URL은 한 번만 저장합니다.
- RSS별 오류는 Actions 실행 로그에 남기며, 다른 RSS는 계속 처리합니다.
- JSON이 바뀌었을 때만 커밋합니다.

## 읽기 시간 계산

- 본문 확보: `ceil(본문 글자 수 / 500)`분, 최소 1분
- 본문 미확보: 요약 글자 수 기준으로 계산하되 최소 3분, `estimated: true`

현재 코드는 요약을 생성형 AI로 새로 작성하지 않습니다. RSS가 제공한 요약을 우선 사용하고, 없으면 본문 앞부분을 100자 이내로 잘라 저장합니다. 따라서 `summary`는 짧은 요약/발췌문입니다.

## 운영상 참고

- GitHub Actions의 예약 실행은 부하 등에 따라 예정 시각보다 늦어질 수 있습니다.
- RSS 제공자별 이용약관과 저작권 정책을 확인하세요. RSS에 포함된 요약문을 저장·재배포할 수 있는 범위도 매체별로 다를 수 있습니다.
- 외부 사이트의 본문 추출은 사이트 구조, 차단, 유료 구독벽에 따라 실패할 수 있습니다.
